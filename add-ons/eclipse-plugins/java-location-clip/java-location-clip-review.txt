java-location-clip 全体設計・命名レビュー

対象: add-ons/eclipse-plugins/java-location-clip
レビュー日: 2026-10-04
レビュー対象: 未コミット変更を含む現在の実装

総評

UI・JDTからの変換・モデル・文字列整形を分ける方向性は良いです。
domain が Eclipse API に依存していない点、TypeLocation と MethodLocation を
分けてフィールドを final にした点は維持したい設計です。

改善点（優先順）

1. JavaLocationResolver の名前と戻り値が一致していない
   対象: src/main/java/com/example/application/JavaLocationResolver.java:18
         src/main/java/com/example/application/MethodProcessor.java:22
   Resolver は位置情報ではなく JavaLocationProcessor を返しています。
   さらに buildClipText() が検証・モデル生成・整形を実行するため、
   処理の境界が呼び出し側から見えにくくなっています。
   今の規模なら、Resolver が検証済みの位置情報を返し、続いて Formatter を
   呼ぶ構成を推奨します。現在の構成を維持するなら、
   JavaLocationProcessorFactory.create(...) の方が実態に合います。

2. 選択失敗時の扱いに一貫性がない
   対象: src/main/java/com/example/application/JavaLocationResolver.java:24
         src/main/java/com/example/presentation/ClipJavaLocationHandler.java:29
   空選択と対象外要素はエラー通知になりますが、要素を取得できない場合は
   OperationIgnoredException によって無反応になります。
   エディタがないなどの実行対象外は早期 return、Javaエディタ内での選択不備は
   InvalidSelectionException とすると理解しやすくなります。
   正常な無操作を表すためだけの OperationIgnoredException は省略できると考えます。

3. 小さなクラスへの分割が処理を追う負担になっている
   対象: src/main/java/com/example/domain/TypeSelection.java:3
         src/main/java/com/example/domain/TypeValidator.java:5
         src/main/java/com/example/domain/MethodSelection.java:3
         src/main/java/com/example/domain/MethodValidator.java:5
   TypeSelection は文字列一つを保持し、TypeValidator は文字列比較だけを行います。
   メソッド側もほぼ同じ構造です。
   個別に拡張する予定がなければ、選択情報を一つにまとめ、名前の検証を共通化して
   十分です。一方、型とメソッドで必須情報が異なる TypeLocation / MethodLocation
   の分割には意味があります。
   これらのコンストラクタで必須値と正の行番号を検証すると、モデルの契約も
   明確になります。

4. 配布用プラグインとしての設定が不足している
   対象: pom.xml:124
   POM は plugin.xml と META-INF/MANIFEST.MF を参照していますが、
   対象ディレクトリにはありません。
   単独でビルド・配布する想定なら整備が必要です。
   Handler の登録先も、現在の presentation パッケージと一致させる必要があります。

命名の改善案

・ClipJavaLocationHandler → CopyJavaLocationHandler
  操作がコピーであることを明示します。
・buildClipText() → buildClipboardText()
  略語の曖昧さを解消します。
・MethodLocation.className → typeName
  TypeLocation と用語を統一します。
・lineNumber → selectionStartLineNumber
  メソッド宣言行ではなく選択開始行であることを明示します。
・context → selection
  TypeSelection / MethodSelection と名前を一致させます。
・TypeValidator / MethodValidator → TypeSelectionValidator / MethodSelectionValidator
  個別のクラスを維持する場合、実際に検証する対象を明示します。

JavaLocationMapper、JavaLocationFormatter、formatType() / formatMethod() は
現在の責務に合っています。
型を扱うメッセージも「クラス名」から「型名」に統一すると、コードとの対応が明確です。

推奨する処理の流れ

CopyJavaLocationHandler
  → JavaLocationResolver: 選択の検証・位置情報の取得
  → TypeLocation / MethodLocation
  → JavaLocationFormatter: 文字列整形
  → Handler: クリップボードへの書き込み・結果通知

旧レビューから解消された点

・位置情報モデルは TypeLocation / MethodLocation に分割され、フィールドが
  final になっています。setter による変更を前提とした旧指摘は解消されています。
・JavaLocationMapper はメソッド名を method.getElementName() から取得しています。
  選択文字列からメソッド名を取得することへの旧指摘は解消されています。
・型名の検証が追加され、行番号は取得時に1始まりへ変換されています。
・旧 OperationCanceledException は OperationIgnoredException に置き換えられています。
  名称は改善されていますが、無操作と不正な選択の扱いには上記の検討余地があります。
